# YZU Auto Login

Windows 11 常驻托盘的扬州大学校园网自动登录工具。程序不显示主窗口，WebUI 仅监听本机回环地址；锁屏不会影响当前用户会话中的运行。

## 当前阶段

已实现托盘常驻、本机 WebUI、AES-GCM 加密配置、可配置的连通性探测与日志。检测到校园网门户后，程序会执行统一认证登录，并按 WebUI 中选定的运营商服务（联通 / 移动 / 电信互联网服务，默认“电信互联网服务”）完成认证；提交后会立即重新探测，确认网络恢复。

## 开发运行

```powershell
go mod tidy
go build -ldflags="-H=windowsgui" -o YZUAutoLogin.exe .
.\YZUAutoLogin.exe
```

首次启动会在可执行文件同级目录创建 `config.json`、随机生成的 `secret.key` 和 `logs\app.log`。在浏览器打开 `http://127.0.0.1:8765`，填写账号、密码与运营商服务并保存。密码由 AES-GCM 加密；请勿丢失或泄露 `secret.key`，它必须与 `config.json` 一起保留。旧版本的配置文件没有 `service` 字段，加载时会自动补为默认的“电信互联网服务”。

默认探测要求 `http://www.msftconnecttest.com/connecttest.txt` 返回精确的 `Microsoft Connect Test` 正文；任何其他响应都会作为门户拦截处理。可在 WebUI 调整探测地址、预期正文与预期状态码；**两者至少要填一个**，否则探针就没有判据：门户只要回一个 200 的拦截页，就会被当成“网络正常”，机器永远不会去登录。IP 直连探针（如 `http://223.5.5.5/`）不返回固定正文，应改用预期状态码 `404`。

探测或认证失败只会更新状态并写入日志，程序不会自行退出。认证提交若因连接问题未完成——例如未认证时到统一认证主机的 TLS 握手被拖断——会在本轮内以固定间隔重试至多 `loginAttempts` 次，避免为一次瞬时失败干等一整个探测间隔；提交已经完成的失败（门户拒绝、验证仍被拦截）不会被重复提交，仍等到下个探测周期。

## 门户发现与网络自愈

探测按候选链逐个尝试，命中即停：

1. WebUI 中配置的探测地址；
2. 本机默认网关——有些门户就架在网关上，直接访问会给出带 `wlanuserip` 的 `/eportal/index.jsp` 地址；
3. 内置的 IP 直连探针 `http://223.5.5.5/` 与 `http://119.29.29.29/`（阿里与腾讯的公共解析器，正常应答均为 404）。

第 3 步针对中继校园网场景。中继链路有时只坏 DNS，配置的探测地址在域名解析阶段就失败（日志表现为 `no such host`），HTTP 请求根本没发出去，门户的拦截与重定向自然无从发生。门户按 HTTP 拦截流量且不区分 Host，所以换成 IP 字面量仍能拿到响应，DNS 故障不再让门户“隐身”。只配置一个探针时，任何一种失败都会中断整轮探测；现在单个候选失败只被记录，接着试下一个。

IP 探针必须带预期状态码，因为裸 IP 没有固定正文可比对：正常联网时 `223.5.5.5` 稳定返回 `404`，而未认证时门户会用它自己的拦截页来作答。缺少状态码校验时，程序只能看到“有个 200 响应”，于是把拦截页当成联网证据——这正是“没登录却一直显示网络正常”的成因。现在状态码不符会判为门户拦截，交由后续候选继续查找登录地址。内置的 IP 探针都自带预期状态码；自己填 `probe_url` 为 IP 时，记得同时填上 `预期状态码`。

当所有候选都不可达时，按副作用从小到大恢复：

1. 网关存在但域名解析失败 → 清理 DNS 缓存后重探；
2. 完全没有默认路由 → 执行 `ipconfig /release` 与 `ipconfig /renew`，轮询等待路由表收敛，然后重探。

第 2 步是唯一会中断连接的操作：它会让本机立刻丢失地址并断开当前所有连接，因此只有当路由表确实为空时才触发，并且两次重启之间强制间隔 5 分钟，避免在探测间隔较短时把网卡反复拉断。该步骤需要管理员权限。

日志会区分故障类型（`DNS 解析失败`、`DNS 解析超时`、`连接超时`、`无法建立连接`、`请求失败`），便于判断问题卡在哪一层，而不再是笼统的“探测失败”。

`-H=windowsgui` 会避免启动时出现控制台窗口。

## 门户接入所需信息

当前登录流程依据 2026-08-20 抓取的 HAR 实现。运营商服务的可选值定义在 `portal.go` 的 `portalServices` 中，WebUI 下拉框与登录请求共用这一份列表，选中的服务同时写入 eportal 的服务偏好 Cookie 和 `loginOfCas` 请求的 `service` 字段。若校园网更新了统一认证页面、出现验证码，或调整了服务名称，请同步更新该列表并重新抓取从登录到联网成功的 HAR 以便适配。不要外传含有账号、Cookie 或令牌的 HAR 文件。
